# MetaGPT Research

## Status

`EXPLORE` / supporting research only.

This document preserves SSSF-relevant findings from:

- **MetaGPT: Meta Programming for a Multi-Agent Collaborative Framework**
- arXiv: `2308.00352`

MetaGPT is a source of structured-handoff/SOP ideas, not an authorization to adopt its simulated software-company role hierarchy.

## Governing interpretation

Preserve the structure that prevents conversational information loss, but move stable sequencing and readiness logic into CODE.

> **Replace conversational handoffs with explicit contracts; then eliminate the handoff where deterministic CODE can own the transition.**

## EXPLORE-1 — Structured handoffs over free-form conversation

Consequential phase/worker outputs should be typed, provenance-bearing artifacts/results rather than ambient agent chat.

## EXPLORE-2 — SOPs are inputs to purification, not runtime authority

Human SOPs can reveal durable invariants, dependencies, role boundaries, and verification obligations. Extract those semantics and implement them with the smallest sufficient combination of contracts, CODE, and bounded semantic nodes.

Do not copy human job-title/process structure literally into DSH.

## EXPLORE-3 — Derived artifacts remain subordinate to requirements

Generated PRDs, architecture plans, task plans, diagrams, and handoffs are derived execution hypotheses. They do not supersede the authoritative WorkPackage/requirement ledger.

Every material semantic transformation should preserve requirement lineage.

## EXPLORE-4 — Roles require a real boundary

A durable role/child exists only where there is a genuine distinction in capability, information, authority, independence, objective, or model/profile. Human organizational labels alone do not justify computational roles.

## EXPLORE-5 — Prerequisite readiness is CODE-owned

Once dependencies are typed, CODE determines when a downstream node is runnable. Agents should not monitor ambient messages and rediscover deterministic readiness state.

## EXPLORE-6 — Executable feedback outranks semantic self-review

Mechanically observable properties should be checked through deterministic execution/validators and returned as typed observations. Bounded semantic repair may consume that evidence.

## EXPLORE-7 — Reject ambient global message pools/shared cognition

Prefer dependency-directed typed result transport from explicit producer to admitted consumer. Global message pools/shared conversational memory are not the target SSSF coordination substrate and must not undermine maker/checker independence.

## EXPLORE-8 — QA separates diagnostic feedback from independent checking

Builder-generated tests/self-checks are diagnostic evidence. Where maker/checker independence is required, a separately qualified checker derives obligations from authoritative requirements under a narrower non-maker capability profile.

## EXPLORE-9 — Fewer semantic transformations when possible

Every additional role/artifact introduces another opportunity for requirement distortion. Add semantic stages only when they reduce real uncertainty or establish a required independence/capability boundary.

## EXPLORE-10 — Evaluate SOP/role changes empirically

Do not assume familiar human processes are computationally optimal. Compare role/workflow variants through controlled harness experiments with model, ACI, environment, budgets, requirements, and acceptance held constant where possible.

## Non-decisions

This research does **not** authorize:

- MetaGPT adoption;
- Product Manager / Architect / Project Manager / QA as permanent SSSF roles;
- global shared agent memory/message pool;
- prompt-driven SOP sequencing as outer workflow authority;
- new FUT/roadmap promotion.
